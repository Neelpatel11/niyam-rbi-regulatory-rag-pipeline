# Operations

## Local development

```bash
cp .env.example .env               # add ANTHROPIC_API_KEY
docker compose up -d db
uv sync --all-extras --group dev
uv run niyam init-db
uv run niyam ingest rbi --match "Know Your Customer|Digital Lending|Fraud" --limit 40
uv run niyam embed
uv run niyam ask "How often must a bank update KYC for high risk customers?"
uv run niyam serve                 # API on :8000
cd web && npm install && npm run dev   # UI on :3000
```

Without Docker, the test suite starts an embedded Postgres with pgvector through `pgserver`, so
`uv run pytest` works on a laptop with nothing else installed.

## Ingestion

| Command | Effect |
|---|---|
| `niyam ingest rbi` | All Master Directions. About 380 detail pages at one request every 2 s on a cold cache. |
| `niyam ingest rbi --match REGEX --limit N` | A subset, by title or department. |
| `niyam ingest rbi --id 13141 --id 13109` | Specific directions. |
| `niyam ingest rbi --refresh` | Ignore the HTTP cache. Without it, cached pages younger than `NIYAM_FETCH_CACHE_MAX_AGE_S` (20 h) are reused, so a daily run refetches everything and same-day re-runs are free. |
| `niyam ingest local PATH...` | Markdown with front matter, or PDFs with a sidecar `.yaml`. |
| `niyam ingest ... -c structure-v1 -c fixed-512` | Build several chunk sets at once (for ablations). |
| `niyam embed -c structure-v1 --model BAAI/bge-base-en-v1.5` | Embed one chunk set with another model. Only missing vectors are computed. |

Re-ingesting is idempotent. Documents whose parsed content hash is unchanged are skipped, and
chunks whose text is unchanged keep their IDs and vectors.

The crawler identifies itself with `NIYAM_FETCH_USER_AGENT`, waits `NIYAM_FETCH_MIN_DELAY_S`
between requests to the same host, retries only transient errors, and caches every response on
disk.

## Deploying to GCP

Terraform in `infra/terraform` creates Artifact Registry, Cloud SQL (Postgres 16 with pgvector),
Secret Manager entries, the API and web Cloud Run services, the ingestion Cloud Run Job and a
daily Cloud Scheduler trigger.

```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars          # fill in project and images
terraform init
terraform apply -target=google_artifact_registry_repository.images

REPO=asia-south1-docker.pkg.dev/<project>/niyam
gcloud auth configure-docker asia-south1-docker.pkg.dev
docker build -t $REPO/api:$(git rev-parse --short HEAD) . && docker push $REPO/api:$(git rev-parse --short HEAD)

terraform apply                                        # first apply creates the API; note api_url
docker build --build-arg NEXT_PUBLIC_API_URL=<api_url> -t $REPO/web:<sha> web && docker push $REPO/web:<sha>
terraform apply -var web_image=$REPO/web:<sha> -var 'cors_origins=["<web_url>"]'

printf '%s' "$ANTHROPIC_API_KEY" | gcloud secrets versions add niyam-anthropic-api-key --data-file=-
gcloud run jobs execute niyam-ingest --region asia-south1 --wait   # first load
```

Notes:

- The Anthropic key is added out of band so it never lands in Terraform state. The database
  password is generated by Terraform and therefore *is* in state: keep state in a private bucket.
- `NEXT_PUBLIC_API_URL` is compiled into the web bundle, so the web image is built after the API
  URL is known.
- The configuration was written against the `hashicorp/google` 6.x provider and has not yet been
  applied end to end. Run `terraform validate` and `terraform plan` before the first apply.

## Cost controls

- `api_max_instances` (default 3) and `NIYAM_RATE_LIMIT_PER_MINUTE` (default 30 per client) cap
  LLM spend under load. The rate limiter is per instance.
- The refusal gate skips the LLM entirely for out-of-scope questions.
- Query rewriting only runs for follow-ups and dated questions.
- Context is capped at 8 passages and 6,000 tokens; output at `NIYAM_LLM_MAX_OUTPUT_TOKENS`.
- Embeddings and reranking run locally: no per-query cost.
- Every query records its cost in `queries.cost_usd`:

  ```sql
  SELECT date_trunc('day', created_at) AS day, count(*), sum(cost_usd), avg(cost_usd)
  FROM queries GROUP BY 1 ORDER BY 1 DESC;
  ```

- Set a spending limit on the provider account and a GCP budget alert for a public demo.
- For a public demo, set `NIYAM_API_KEYS` and route the UI through a server-side proxy, or keep
  the API public with the rate limit and instance cap above.

## Observability

- Structured JSON logs with `NIYAM_LOG_JSON=true`.
- `/healthz` (process) and `/readyz` (database) endpoints.
- `queries` stores timings per stage, token usage, cost, retrieved and cited chunk IDs, and the
  pipeline configuration for every request. `feedback` links ratings to those rows.
- Langfuse tracing with `NIYAM_LANGFUSE_ENABLED=true` and the standard `LANGFUSE_*` variables:
  one trace per question with spans for rewrite, retrieval and generation.

Useful queries:

```sql
-- refusal rate and latency by day
SELECT date_trunc('day', created_at) AS day,
       avg((status <> 'answered')::int) AS refusal_rate,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY (timings_ms->>'total')::float) AS p95_ms
FROM queries GROUP BY 1 ORDER BY 1 DESC;

-- answers users disliked, to add to the golden set
SELECT q.question, q.answer->>'text', f.comment
FROM feedback f JOIN queries q USING (trace_id)
WHERE f.rating = -1 ORDER BY f.created_at DESC;
```

## Adding an embedding model

```bash
niyam embed -c structure-v1 --provider fastembed --model BAAI/bge-base-en-v1.5
niyam eval run -n hybrid-rerank-bge-base --split test
```

A new partial HNSW index is created for the model automatically. Switching production to it is a
configuration change (`NIYAM_EMBEDDING_MODEL`); the old vectors stay until deleted:

```sql
DELETE FROM embedding_models WHERE name = 'fastembed:BAAI/bge-small-en-v1.5';  -- cascades
```
